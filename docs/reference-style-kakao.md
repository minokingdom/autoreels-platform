# 카카오톡 URL → 오토릴스 스타일

## 승인형 개발 흐름 (2026-11-23 변경)

`!분석 URL` → 분석 → 기존 구성 또는 새 효과 구현 → 테스트/원본 비교 MP4 → **승인 대기** → `!스타일승인 <10자리 코드>` → 등록·배포 검증. `!스타일보류 <코드>`는 미등록 상태로 보류한다. 아래의 초기 자동 등록 설명은 이 승인 단계로 대체한다.

- 지원하지 않는 효과의 422 응답은 분석 실패로 끝내지 않고 `development` 단계로 이동한다.
- 새 효과 코드는 PC Codex가 읽기 전용 격리 자료/이미지에서 생성한다. 외부 네트워크와 프로젝트/SSH/계정 파일을 모델 명령에 주지 않는다. 생성 함수는 Canvas 2D 전용 AST 허용 목록을 통과해야 하며 모델이 만든 Node 테스트는 실행하지 않는다.
- 신뢰된 실행기가 스타일 스키마, 컷 경계/역순 탐색, 세로 해상도, 빈 사진/한 장, 캔버스 상태, 브라우저 오류를 검사하고 원본과 나란히 비교 영상을 만든다. 검증 오류는 최대 두 차례 보정한다. 임의로 유사 스타일에 등록하지 않는다.
- 분석 결과가 기존 효과만 사용하더라도 비교 영상을 먼저 보내고 승인받는다.
- 비교 MP4는 기존 Iris 영상 전송으로 본인 테스트방에만 보낸다. 전송이 불명확하면 자동 재발송하지 않고 승인도 막는다.
- 승인 코드는 후보 JSON/렌더 코드, 원본, 비교 영상, 검사 기록, 엔진 버전의 SHA-256 묶음에 연결된다. Iris 원문·발신자·방·메시지 신선도를 기존과 동일하게 검증한다. 전달된 승인 명령, 다른 사용자/방, 과거 승인 재사용은 허용하지 않는다.
- 승인은 카탈로그 한 행 및 필요한 전용 렌더 파일만 원자적으로 등록한다. 원본 영상/음악/인물/로고는 저장소에 올리지 않는다. 같은 원본 중복 등록은 차단하며 GitHub 최신 카탈로그 SHA 충돌은 실패로 남긴다.
- 기존 `deployed`의 Vercel+smoke+라이브 확인은 유지한다. 테스트 실패를 승인으로 우회하지 않는다.
- 과거 실패한 특정 건을 사용자가 재개 요청한 경우 SSH 운영 채널 `resume_development`만 사용한다. 기존 실패 기록은 meta 감사 기록에 보존한다. 카카오 메시지 위조나 `started`/결과 파일 삭제로 재실행하지 않는다.

현재 비교 대상: [사진 콜라주 포커스](reference-collections/photo-montage-20261123.md).

모비스 1:1 테스트방에서 운영자가 `!분석 https://...`를 보낸다. 공유 문구와 줄바꿈이 있어도 URL 하나만 추출한다. Facebook 릴스·동영상, YouTube/Shorts, Instagram 게시물·릴스, TikTok, Vimeo, Pinterest의 공개 영상 또는 CapCut 템플릿 공개 미리보기 1개, 최대 180초/200MB를 받는다. Facebook의 `/share/r/`, `/share/v/`, `fb.watch` 공유 링크는 작업기가 Facebook 공식 영상 주소로 이동해 영상 ID를 확인한다. 로그인·다운로드 차단은 우회하지 않는다.

## 실행 구성

- 수신: 기존 Iris → `/home/mino/eatspay-kakao/eatspay_kakao_bot.py` → `autoreels_style_commands.py`.
- 기존 `mobis_agent.AgentCommands`의 Iris 원문·메시지 ID·발신자·120초 신선도·현재 1:1방 검증을 재사용한다.
- 별도 SQLite 큐는 `/home/mino/eatspay-kakao/autoreels-style/queue.sqlite`. 동일 메시지/진행·완료된 동일 URL을 중복 실행하지 않는다.
- Windows 작업기: `D:\AutoReelsLocal\StyleLab\style_worker.py`, 독립 `.venv`와 rea-video. Windows 로그인 작업 `AutoReels-StyleLab`.
- 작업기는 기존 Tailscale SSH로 큐를 조회한다. PC에 외부 수신 포트를 열지 않는다. PC가 꺼져 있으면 분석만 대기하며 기존 고객 영상 생성은 영향 없다.
- 실행 Python은 UTF-8 모드. 출력·분석 자료·오류·등록 체크포인트는 D:의 `jobs/<메시지ID>`에 보관한다.

## 처리와 비용

1. yt-dlp로 URL을 검증하고 공개 영상 하나를 다운로드한다. CapCut 공유 링크는 상세 주소로 정규화하고 공개 미리보기의 파일 크기와 영상 길이를 확인한다. 사용자 쿠키와 브라우저 세션을 가져오지 않는다.
2. rea-video로 컷·움직임을 분석한다. 현재는 OCR/ASR/분리 모델을 사용하지 않으므로 정확한 글꼴 이름·자막 시간·음성 출처는 미측정이다.
3. 시간순 JPEG 12장과 제한된 측정 타임라인을 `/api/generate-script`의 `mode:reference-style-worker`에 전용 인증키로 보낸다. 회원용 `reference-style`은 로그인 보호를 유지한다. 서버의 Gemini 시각 분석을 사용하며 일일 서비스 한도·전체 예산 한도를 적용한다. 공급자 키는 PC에 복사하지 않는다. 같은 요청 번호는 중복 실행하지 않는다. 분석용 텍스트/이미지 입력 비용이 발생하며 새 이미지·AI 동영상 생성은 하지 않는다. 인증 설정과 복구는 `docs/style-worker-auth-20261122.md`를 따른다.
4. `lib/reference-style.cjs`가 이름·분류·색상·구도·글꼴 후보·자막 위치·등장 효과·사진 움직임의 범위를 검증한다. 임의 JavaScript/HTML을 받지 않는다. 원본 등장인물/대사/로고/음악은 스타일에 넣지 않는다.
5. 고정된 GitHub 저장소의 `public/assets/reference-styles.json` 한 파일만 최신 SHA를 기준으로 갱신한다. 다른 작업 중인 소스를 커밋하지 않는다. 원본 URL과 영상은 공개 카탈로그에 포함하지 않는다.
6. Vercel 성공, 해당 커밋의 GitHub smoke 성공, 라이브 app.js의 스타일 ID 존재까지 확인한 뒤 같은 방에 완료 안내한다. 실패·지원 불가·배포 미확인은 완료로 보고하지 않는다.

## 지원 범위

전체 사진/여백/폴라로이드 구도, 팔레트, 글꼴 후보, 자막 상·중·하 배치, 페이드·상승·마스크·단어 강조, 사진 줌·좌우 이동, 컷·디졸브를 조합한다. 원본 효과를 똑같이 재현하는 범용 코드 생성기가 아니다. 핵심 효과가 3D·인물 애니메이션·오브젝트 추적이면 별도 렌더 구현 필요로 종료한다.

`diagonal-fan`(사선 멀티 마스크)은 여러 컷 사진을 사선 다각형으로 겹쳐 펼치는 전용 구성이다. 편집기 화면 녹화에 보이는 해당 전환도 UI를 제외하고 분석할 수 있다. 기존 `diagonal`은 같은 사진 한 장을 잘라 보여 주는 구성으로 그대로 유지한다. 구현 근거와 검증은 `docs/reference-collections/diagonal-fan-20261122.md`에 기록한다.

`07-reference-styles.js`는 빌드 시 검증된 데이터만 읽어 기존 디자인 목록에 추가한다. 음성 기반 리타이밍, 컷별 사진, 기존 명함 엔딩을 사용한다. 원본 영상 길이·컷 수로 고객 대본을 바꾸지 않는다.

## 점검·복구

`python autoreels_style_commands.py`에 SSH stdin JSON `{"op":"status"}`를 보내 최근 상태를 확인한다. 실제 메시지를 위조해 웹훅을 시험하지 않는다. 큐의 claim token은 로그·보고에 쓰지 않는다. 전송 결과가 불명확한 카카오 알림과 실행 중단 작업은 자동으로 재실행하지 않는다.

작업기 시작 흔적 `started`와 `published.json`을 임의 삭제하지 않는다. 카탈로그가 등록됐지만 배포 확인이 실패했다면 해당 커밋·Vercel·smoke를 먼저 확인한다. 자동 등록은 쉘 코드가 아니라 검증된 스타일 JSON 한 건으로 한정된다.

검증: `python scripts/alerts/test_style_commands.py`, `node --test tests/reference-styles.cjs`, `node tests/reference-styles-browser.mjs`, `node tests/smoke-render.mjs`, `node tests/narration-continuity.mjs`, `node tests/narration-browser.mjs`.

## 스튜디오의 개인 참고 영상

갤러리 영상과 브라우저에서 읽을 수 있는 영상 파일 링크는 휴대폰에서 컷, 한국어 화면 문구와 대사를 분석합니다. CapCut 공유 링크는 로그인 후 계정 API가 공개 미리보기의 주소·제목을 찾고, 휴대폰이 해당 CDN에서 영상을 직접 받습니다. 유튜브 쇼츠·인스타그램·틱톡 공유 페이지의 영상 바이트는 갤러리 파일로 제공해야 합니다.

각 휴대폰 탭은 자체 분석 및 대본 수정을 실행합니다. 명시한 단어는 기기에서 교체하며 자유로운 수정은 로컬 대본 모델을 처음 사용할 때 내려받습니다. 사용 중인 탭에는 분석 결과를 1시간 동안 복원할 수 있습니다. 운영자 카카오톡 스타일 등록은 기존 작업기를 사용합니다. 이전 스튜디오 버전의 대기 요청은 기존 회원 전용 API로 처리합니다.

검증은 `node tests/private-remix-browser.mjs`로 직접 링크와 실제 한국어 OCR, 로딩바, 대본 수정, 새로고침 복구, 서버 대기열 미사용을 확인합니다.
