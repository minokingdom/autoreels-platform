# 오토릴스 예약 실행·문자 인증 설정

2026-11-17. 결제 설정은 이 변경에 포함하지 않습니다.

## 지금 사용 가능한 기능

- 계정의 `내 프로젝트`에서 사진·대본·컷 편집·명함·음성/BGM 설정 저장 및 불러오기. 저장한 마지막 프로젝트를 같은 기기 새로고침 시 복원합니다. 다른 기기는 로그인 후 목록에서 선택합니다.
- 계정당 5개, 각 JSON 전체 2MB. 사용자 사진은 최대 긴 변 1080px JPEG로 보관합니다. 사진 스티커·로고는 PNG를 사용합니다. 기본 서비스 사진은 경로로 참조합니다. DB는 인증된 계정 API로만 접근합니다.
- 생성 음성 파일은 저장하지 않고 대본으로 다시 생성합니다. 직접 올린 동영상·MP3가 있으면 저장을 거부하고 안내합니다. 저장 버튼을 누르지 않은 편집은 자동 저장되지 않습니다.
- 내 계정 → 계정 보안에서 비밀번호 변경, 다른 기기 로그아웃.
- 발행 단계 → 예약·발행 내역에서 최근 50개 상태와 실패 이유 확인, 시작 전 예약 취소. 해당 요청의 모든 대상이 실패/취소된 경우에만 이용 횟수를 한 번 복구합니다.

## 문자 인증 (SOLAPI)

1. SOLAPI 계정에서 발신번호를 사전 등록하고 사용할 API Key/Secret을 만듭니다. 문자 발송은 해당 서비스 비용이 발생합니다.
2. Vercel의 AutoReels 프로젝트 → Settings → Environment Variables에 아래 값을 Production 환경으로 등록합니다. 비밀값은 채팅·GitHub·프런트 코드에 넣지 않습니다.

| 이름 | 값 |
| --- | --- |
| `SOLAPI_API_KEY` | 발급받은 API Key |
| `SOLAPI_API_SECRET` | 발급받은 API Secret |
| `SOLAPI_FROM` | 등록 완료된 발신번호, 숫자만 |

3. 재배포한 뒤 `/api/account?action=config`의 `phoneVerification:true`를 확인합니다.
4. 본인 번호로 가입 인증과 비밀번호 찾기를 각각 실제로 검사합니다. 가입 시 문자를 받기 전에는 계정을 만들지 않습니다. 인증번호는 5분·최대 5회 입력·한 번 사용, 재발송 1분 간격입니다. 번호당 하루 5회, IP당 시간당 10회, 전체 하루 200회로 제한합니다. 발송 실패·타임아웃도 발송 예산을 돌려주지 않아 반복 과금을 막습니다.

서비스 연결 전에는 기존 계정 로그인·비밀번호 변경이 가능하며 **신규 가입·문자 복구는 준비 중**으로 표시됩니다. DB의 `phone_verified_at`가 비어 있는 기존 회원을 인증 완료로 간주하지 않습니다. 회원 탈퇴·기존 회원의 별도 번호 인증 화면은 후속 작업입니다.

공식 자료: [발신번호 및 발송 API](https://solapi.com/developers/api/messages), [API Key 서명](https://solapi.com/developers/api/authentication-api-key).

## 1분 예약 실행

현재 저장소의 Vercel 기본 크론은 하루 한 번입니다. 이를 정시 예약용으로 사용하지 않습니다. Vercel 요금제를 임의로 바꾸거나 외부 서비스를 결제하지 않습니다.

외부 HTTP 스케줄러(예: cron-job.org)에서 다음 한 개 작업을 등록합니다.

| 설정 | 값 |
| --- | --- |
| 주소 | `https://autoreels-studio.vercel.app/api/cron-sns` |
| 방식 | GET |
| 주기 | 매 1분 (`* * * * *`) |
| 요청 헤더 | `Authorization: Bearer <Vercel에 설정한 CRON_SECRET>` |
| 성공 판정 | HTTP 200 및 JSON `ok:true` |
| 타임아웃 | 60초 이상 지원하는 실행 서비스 |

Vercel Production에 충분히 긴 임의 `CRON_SECRET`와 `SNS_SCHEDULING_ENABLED=true`를 설정하고 재배포합니다. `CRON_SECRET`은 URL 쿼리에 넣지 않습니다. 스케줄러의 비밀 헤더 저장 기능을 사용합니다.

예약은 연속 3회 워커 성공 후 열립니다. 최근 성공이 150초를 넘으면 신규 예약을 다시 차단합니다. 화면을 새로고침하면 설정이 반영됩니다. 브라우저를 닫아도 서버가 실행합니다. 예약은 2분 뒤~7일 이내, 계정당 대기 50개이며 지정 시각부터 순서대로 처리합니다. **플랫폼 인코딩·승인 시간과 대기열 때문에 실제 게시 시각이 늦을 수 있습니다.** 실행 한 회당 신규 4개·진행 중 4개를 확인하며 대규모 트래픽 전에는 전용 큐가 필요합니다.

저장된 영상 읽기가 실패한 경우만 1분 뒤 최대 2회 재시도합니다. 외부 게시 응답이 불명확한 경우는 `review`로 남겨 중복 게시를 막습니다. 15분 넘게 실행하지 못한 예약은 실패 처리하고 이용 횟수 복구 대상으로 둡니다. 스케줄러의 실패 알림을 운영자에게 설정하고, 앱 안의 예약·발행 내역을 확인합니다. 별도의 SMS/이메일 실패 알림은 아직 보내지 않습니다.

확인 절차: 테스트 계정의 SNS에 짧은 영상 예약 → 브라우저 종료 → 지정 시각 이후 내역 확인 → 실제 SNS 게시 확인 → 시작 전 취소/워커 중단/저장소 실패 확인. 이 실발행 검증 전에는 전체 자동 발행 검증 완료로 보고하지 않습니다.

## 검증 범위 및 남은 운영 작업

PGlite 테스트는 실제 PostgreSQL SQL·트랜잭션을 사용하지만 단일 연결이라 advisory lock 경쟁 검증은 별도 운영 DB 부하 테스트가 필요합니다. 브라우저 프로젝트 테스트는 저장 API 응답을 모의 처리합니다. 실제 SMS 전달·SNS OAuth 및 게시·모바일 기기 검증은 서비스 연결 후 진행합니다.

운영 DB 백업·복구 훈련, 비용/실패 알림, 회원 탈퇴, 사용자 동영상·MP3를 포함한 대용량 저장은 별도 남은 작업입니다. 결제 변경은 이 배포에서 하지 않습니다.
