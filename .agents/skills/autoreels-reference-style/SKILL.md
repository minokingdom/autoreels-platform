# AutoReels URL 스타일 분석

실제 저장소는 `C:/Users/ektjt/.gemini/antigravity/scratch/dealer-reels-platform`이다. 저장소의 `AGENTS.md`, `docs/reference-style-kakao.md`, `docs/design-system.md`를 먼저 확인한다.

사용자 입력은 기존 모비스 1:1 카카오방의 `!분석 URL`이다. CLI 독립 실행이나 일반 사용자용 공개 입력창으로 바꾸지 않는다. `scripts/alerts/autoreels_style_commands.py`는 기존 Iris 원문/발신자 검증을 사용한다. 기존 이츠페이 알림/명령 큐와 스타일 큐는 별개다.

rea-video는 `D:/AutoReelsLocal/StyleLab/.venv`에 설치되어 있다. 분석 결과 `VIDEO.md`, 타임라인, 프레임을 실제로 확인하고 추측과 측정을 구분한다. 자동 처리의 지원 범위는 `lib/reference-style.cjs`의 선언형 설정이다. 지원하지 않는 동작을 비슷한 스타일로 몰래 대체하지 않는다.

사용자가 별도 렌더 구현을 요청하면 원본 영상의 구도와 움직임을 근거로 기존 모션 엔진에 구현한다. 원본 소재·대사는 복사하지 않는다. 컷 수만큼 사진을 사용하고 실제 음성에 맞춰 길이를 계산하며 명함 엔딩 유무를 유지한다.

스타일 등록 완료는 카탈로그 commit만으로 판단하지 않는다. 빌드, 브라우저 렌더, 음성 회귀, Vercel 상태, 해당 commit의 smoke와 라이브 스타일 ID를 확인한다. 분석 모델/API 실패·다운로드 차단·미배포 상태를 숨기지 않는다.

## 사용자 지정 분석 절차 (2026-11-18)

스타일 수집에는 설치된 원본 rea-video 스킬 `D:/AutoReelsLocal/StyleLab/rea-video/skills/rea-video/SKILL.md`도 함께 적용한다. `decompose` 실행만으로 끝내지 않고 `VIDEO.md`, 장면 연락판, `review`와 `apply-review`를 통해 실제 시각 검토를 기록한다. 도구의 실사/AI/3D 추정과 눈으로 확인한 화면이 충돌하면 그 차이와 미확정 사항을 남긴다. 원본 색감·인물 동작까지 구현한 것처럼 설명하지 않는다.

수집 출처·제외 사유·검토 결과는 `docs/reference-collections/`에 기록한다. 사용자가 이 대화에서 직접 요청한 수집 배치는 카카오 메시지를 위조하지 않고 별도로 처리할 수 있으며, 기존 카카오 명령 접수 경로는 유지한다.

## 타임라인 효과 수집

운영자 `!분석 URL` 작업기는 원본을 초당 30프레임으로 축소 샘플링한다. 넓은 영역이 짧게 밝아지고 직전과 비슷한 장면으로 돌아왔을 때만 플래시 후보로 기록한다. 관측 시작·길이·강도는 작업 폴더의 `effect-measurements.json`에서 확인한다. 원본과 밝은 장면 간 단순 컷, 카메라 줌, 잔상과 효과음은 플래시 측정으로 판정할 수 없다. 실제 프레임을 검토할 때는 피사체의 밝기 변화와 조명 효과를 구분하고, 방향·색이 중요한 부분은 별도로 기록한다.

편집기는 카탈로그의 선택적 `effects`를 읽는다. 참고 영상 전체 스타일과 별개로 각 고객이 자기 타임라인에서 효과 위치·길이·강도를 조절한다. 폴라로이드 스톱모션 보류 후보의 82.967초 플래시는 0.267초, 강도 0.41로 측정했다. 프레임에서 확인한 따뜻한 색을 참고한 편집기용 재구성이며, 전체 스타일의 보류 상태는 유지한다.

## 새 테마의 세로 미리보기와 보완 기록

- 공유 URL은 추적 쿼리를 제거한 주소로 기존 수집 기록과 카탈로그를 대조한다. 화면 녹화라면 재생 영역을 잘라 도입·본문·엔딩의 장면과 전환을 각각 본다. 편집 타임라인의 트랙과 작품 안에 그려진 선을 구별한다.
- 사용자가 공개 전에 시안을 요청한 흐름에서는 스튜디오의 실제 디자인 선택 경로로 데모를 렌더링한다. 9:16 완성본을 Chrome에서 먼저 보여주고 원본 동시 비교를 제공한다. 수집, 시안 등록, 운영 배포 상태를 따로 기록한다.
- 레퍼런스에 쓰인 연도·여행 제목·브랜드를 그대로 고정하지 않는다. 첫 컷과 마지막 컷을 서로 다른 한국어 문구로 바꾸고, 긴 문구와 빈 문구에서도 실제 캔버스 결과를 확인한다. 고객 사진으로 교체한 결과, 컷별 음성 경계, 명함 엔딩도 확인한다.
- 패널·마스크 테마는 세로 출력 좌표에서 도형을 그린다. 완전히 열린 프레임에서 사진이 네 모서리를 채우는지, 밝고 어두운 단색 사진을 교체해도 윤곽이 같은지 본다. 하나로 이어져야 할 사선은 공통 직선으로 만들고 패널별 시차는 그 안에서 표현한다. 원본에 실제로 있는 X자나 접힘선은 따로 보존한다.
- 승인 전에는 한 지점의 캡처로 끝내지 않고 같은 도형이 등장하는 모든 구간을 재생·탐색해 검사한다. 비트 마스크의 재현 사례는 `docs/reference-collections/beat-mask-20261128.md`, 문구 교체와 직선 오차 계측 예시는 `tests/reference-styles-browser.mjs`에 있다.
- 매번 추가할 때 발견한 문제, 실제로 고친 방법, 확인한 결과를 해당 테마의 수집 문서에 적는다. 다음 테마에도 반복되는 기준은 이 스킬에 반영하고, 자동으로 확인할 수 있는 회귀는 해당 검사에 넣는다. 기존 기준으로 충분하면 수집 문서에 검증 결과만 남긴다.

- 물체가 일부만 움직이는 테마는 고정 배경과 움직이는 부분을 나눠 검증한다. 회전 디스크는 바깥 픽셀을, 인화기는 슬롯·노출 순서·네 컷 초과 시 다음 묶음을 확인한다. 실제 사례와 회귀 검사는 `docs/reference-collections/disc-booth-20261128.md`와 `tests/reference-styles-browser.mjs`를 따른다.
